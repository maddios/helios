# @partnrup/helios-sdk: agent reference

Dense reference for coding agents. For the narrative and runnable code, read [README.md](./README.md). Every code block here is a verbatim run of lines from `sdk/examples/`, checked by `npm run check:examples -w sdk`.

Helios is a multi-tenant encoding and AI post-processing service. Accounts (bella, novel) encode media from S3 sources, uploads or URLs with a named preset, and get encodes, stills, audio, transcripts, translations and scene analysis back. Progress is delivered as signed webhook events or EventBridge events.

## Rules

- Server-side only. An account key (`sk_live_...`) or admin key (`sk_admin_...`) must never reach a browser. The one browser entry, `@partnrup/helios-sdk/browser`, holds no key: the backend creates, re-signs and completes browser uploads.
- Import the account client from `@partnrup/helios-sdk` and the admin client from `@partnrup/helios-sdk/admin`. Keep `HeliosAdmin` out of account-facing services.
- Pass every value explicitly. The SDK reads no environment variables. Examples read them with a `requireEnv` helper that throws when they are missing.
- Errors are `HeliosError` subclasses with `code`, `status` (absent when no response arrived), `requestId` and `details`. Branch on the class, then on `code`.
- Webhooks: verify the raw body, never re-serialized JSON. Dedupe on `id` (the `Helios-Event-Id` header). Consumers must be idempotent: terminal requests are re-sent after the FIFO dedupe window.

## When to use which method

| Goal                                        | Use                                                                                                                         | Notes                                                                                                   |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Encode a file already in a source bucket    | `encodes.create({ source: { bucket, key }, preset })`                                                                       | Bucket must be allowed for the account. Helios never modifies Kodak-owned objects.                      |
| Upload a local file or stream and encode it | `uploads.uploadAndEncode(input, { preset, ... })`                                                                           | Returns `{ uploadKey, request }`. Failing encode throws `UploadEncodeError` with `uploadKey`.           |

## Browser uploader (`@partnrup/helios-sdk/browser`)

Secret-free and dependency-free: it imports nothing from the account client, and it works in any browser (XHR, Blob). Import it only in the page.

- `uploadParts(upload, file, options?)` takes the `upload` from the backend's `createMultipart` (`{ uploadId, uploadKey, partSizeBytes, parts }`) and a `Blob` or `File`. It returns `[{ partNumber, etag }]` sorted by part number. The backend passes that list to `completeMultipart`.
- `options`: `concurrency` (1-16, default 4), `onProgress({ uploadedBytes, totalBytes })` (never decreases; skipped parts count), `signal` (aborts in-flight parts), `signParts(partNumbers)` (call the backend's renew route; at most once per part on 403), `uploadedParts` (from the backend's `listParts`; they are skipped and validated against the planned size), `maxPartRetries` (0-10, default 3; network errors, 5xx and 429 are retried with backoff).
- `uploadSingle({ url, headers? }, file, { onProgress?, signal? })` PUTs a whole file to a presigned URL from `uploads.presign`.
- Errors are `BrowserUploadError` with `code`: `aborted`, `invalid_option`, `invalid_upload`, `invalid_resume`, `part_rejected`, `upload_failed`, plus subclasses `EtagUnavailableError` (`etag_unavailable`: bucket CORS does not expose `ETag`), `PartUrlExpiredError` (`part_url_expired`: 403 with no renewal, or renewal rejected) and `NetworkError` (`network_error`).
- CORS: the media bucket allows the origins in `UPLOAD_ALLOWED_ORIGINS` for the stage, with `PUT`, `GET` and `HEAD`, and exposes `ETag`. Add each app origin, such as `https://app.example.com` or `http://localhost:5173`, and nothing else.
- Route pattern: `POST /uploads/multipart/{uploadId}/parts` (renew, body `{ uploadKey, partNumbers }`), `GET /uploads/multipart/{uploadId}/parts?uploadKey=` (stored parts), `POST /uploads/multipart/{uploadId}/complete` (finish). The renew route checks that the key belongs to the account and that part numbers are valid, but not that they are within the planned count.

Example: `examples/browserUpload.backend.ts` and `examples/browserUpload.client.ts`, which the README recipe quotes.

## Webhooks and EventBridge

Webhook headers: `Helios-Signature` (`t=<unix>,v1=<hex>`, HMAC-SHA256 over `"<t>.<rawBody>"` with the account secret), `Helios-Event-Id` (stable per event across redeliveries), `Helios-Event` (the event name). Tolerance is 300 s. The SDK checks this with a timing-safe compare and rejects surrounding whitespace and upper-case hex, as the server signs.

Every event body has the same envelope: `{ id, createdAt, sequence, event, data }`. EventBridge delivers the same JSON as `detail`, with `Source` `helios.<accountId>` and `DetailType` equal to `event`. Business fields are under `detail.data`.

| Event               | Emitted when                                                                              | `data`                                                                                                                                                                                                                                                 |
| ------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `item.completed`    | A pipeline item (encode, transcribe, scenes, purge) reaches COMPLETE                      | `requestId`, `assetId`, `item: { key, kind, profile?, status, error? }`, `outputs?` (asset output views with CDN urls, keyed by profile), `transcripts?` (`{ language, isTranslation, urls: { srt, vtt, txt } }`), `scenes?` (`{ sceneCount, title }`) |
| `item.failed`       | An item fails after its retries                                                           | same as `item.completed`, with `item.error`                                                                                                                                                                                                            |
| `item.skipped`      | An item is skipped, for example scenes on an asset with no stills, or a dependency failed | same as `item.completed`                                                                                                                                                                                                                               |
| `item.cancelled`    | An item is cancelled by `requests.cancel`                                                 | same as `item.completed`                                                                                                                                                                                                                               |
| `request.completed` | A request reaches COMPLETE                                                                | `request` (RequestView), `asset` (AssetView)                                                                                                                                                                                                           |
| `request.failed`    | A request reaches ERROR; `request.error` has `code` and `message`                         | `request`, `asset`                                                                                                                                                                                                                                     |
| `request.cancelled` | A request is cancelled                                                                    | `request`, `asset`                                                                                                                                                                                                                                     |
| `asset.deleted`     | A purge request finishes (after `assets.delete`)                                          | `request`, `asset`                                                                                                                                                                                                                                     |
| `helios.test`       | `destinations.test` is called; no delivery row is written                                 | `{ accountId }`, `sequence: 0`                                                                                                                                                                                                                         |

Ordering and duplicates:

- `sequence` is per request, starts at 1, increases in creation order, and can have gaps. Test events use 0. Sort by `sequence` to order one request's events.
- Redeliveries keep the same `id` and `Helios-Event-Id`. Store processed ids and return 2xx for duplicates.
- Request and asset fields reflect the asset at delivery time, so a retry can carry newer data.
- Webhook retries: non-2xx, timeouts and network errors retry after 30 s, 2 min, 10 min, 30 min and 2 h, then the delivery is marked FAILED. `requests.callbacks.list` shows the attempts with status PENDING, DELIVERED, FAILED or SKIPPED (SKIPPED when the request had no destination).
- Destination precedence: the request's `destination` (or `callbackUrl`) overrides the account default.
- EventBridge payloads of 256 KB or more fail at once and are not retried. Trim outputs when a request is large.
- EventBridge bus setup is in [guides/eventbridge.md](./guides/eventbridge.md). Webhook verification is in [guides/webhooks.md](./guides/webhooks.md).

Unknown event types throw `WebhookError` with code `payload_invalid`. Upgrade the SDK before the server starts sending new event types.

## Idempotency and retries

Each SDK method declares its retry mode, and the retry policy test table (`test/unit-retry-policy.test.ts`) pins it.

- `idempotent`: retries 429, 5xx, network errors and timeouts, up to `maxRetries` (default 3, range 0-10).
  - Reads (GET): `health`, `ready`, `openapi`, `assets.list/get/transcripts/scenes`, `requests.get`, `requests.callbacks.list`, `presets.list/get`, `destinations.eventBridgePolicy`, `account.getDestination`, `usage.get`, and the admin reads `accounts.list`, `presets.list/get`, `usage.get`.
  - Reads (GET) also include `uploads.listParts`. `uploads.signParts` is a POST that only presigns, so it is idempotent too.
  - Writes that are safe to repeat: `account.setDestination` (PUT), `assets.delete`, `requests.cancel`, `presets.delete`, `presets.removeProfile`, `uploads.abortMultipart`, `keys.revoke`, `admin.presets.delete` (DELETE).
  - Keyed POSTs, which carry a `requestId`: `encodes.create`, `encodes.reencode`, `assets.postProcess`, `uploads.completeMultipart` only when `encode` is given.
  - `encodes.create(..., { dryRun: true })` is idempotent because it writes nothing.
- `rateLimitOnly`: retries 429 only, so a write the server may already have applied is never repeated. Used for: `assets.setActiveStill`, `requests.callbacks.redeliver`, `uploads.presign`, `uploads.createMultipart`, `uploads.completeMultipart` without `encode`, `files.create`, `presets.create/update/addProfile/updateProfile/clone/dryRun`, `destinations.test`, `admin.accounts.create/update/rotateWebhookSecret`, `admin.keys.create`, `admin.presets.create/update`, `admin.destinations.test`.

Idempotency keys:

- Each keyed create (`encodes.create`, `encodes.reencode`, `assets.postProcess`, `uploads.completeMultipart` with `encode`, `uploadAndEncode`) generates one `requestId` per call and reuses it on every retry. A caller-supplied `requestId` (UUID) is kept.
- To survive a process restart, persist your own `requestId` with the job and pass it again. A repeated `requestId` returns the original request with 200.
- Upload parts retry individually (`partTimeoutMs`, per-part retries). A failing part aborts the multipart upload on the server.
- `UploadEncodeError.uploadKey` lets you re-run only the encode.

Rate limits: `Retry-After` is honoured up to `maxRetryAfterMs` (default 30000). A longer one throws `RateLimitError` at once, with `retryAfterMs`.

Error classes by status: 400 `ValidationError`, 401 `AuthenticationError`, 403 `PermissionError`, 404 `NotFoundError`, 409 `ConflictError`, 422 `UnprocessableError`, 429 `RateLimitError`, 503 `ServiceUnavailableError`, other responses `ApiError`. No response: `ConnectionError`. Timeout: `TimeoutError`. Caller abort: `AbortedError`. Storage: `UploadError`. Stored but encode failed: `UploadEncodeError`. Local config: `ConfigurationError`. Local validation: `ValidationError` without `status`. A 2xx body that is not JSON: `ApiError` with code `invalid_response`.

`request.error.code` values include `unprocessable_source`, `unsafe_url`, `too_large` and `nothing_to_do`. Item errors are plain text in `item.error` and never contain provider output.

| Presigned URLs         | Valid for at least 6 hours (`UPLOAD_URL_EXPIRY_SEC` is at least 21600), so part URLs outlive a long upload                                                                                                                                                                                                                             |
| SDK upload concurrency | 1-16 parts in parallel, default 4. Part timeout default 300000 ms                                                                                                                                                                                                                                                                      |
| Translations           | Up to 20 target languages per request. Duplicates ignored. Codes validated against the language table; unknown codes return 400 listing all                                                                                                                                                                                            |
| Preset name            | `^[a-z0-9][a-z0-9_-]{1,62}$` (2-63 characters). Profile names unique per preset                                                                                                                                                                                                                                                        |
| `externalId`           | 1-255 characters                                                                                                                                                                                                                                                                                                                       |
| Raw file `filename`    | 1-255 characters                                                                                                                                                                                                                                                                                                                       |
| `assets.list` page     | `limit` 1-100                                                                                                                                                                                                                                                                                                                          |
| Usage range            | At most 366 days, `from` not after `to`                                                                                                                                                                                                                                                                                                |
| Image params           | `w`, `h` 1-4096. `q` 1-100. `f` one of `jpg`, `png`, `webp`, `avif`. `c` one of `fit` (default), `fill`, `limit`, `pad`. `g` only with `fill`. `b` six lowercase hex digits and only with `pad`. Image transforms use the same names as the URL grammar: `w`, `h`, `c`, `g`, `b`, `q`, `f`. `images.url` produces exactly the server's canonical form (`c_fit` omitted), so each image has one CDN cache key.

## Versioning

- `package.json` `version` is the SDK version. Publishing happens only from a `sdk-v<version>` tag through `.github/workflows/sdk-publish.yml`.
- The server adds event types and fields over time. The zod schemas ignore unknown fields. An unknown event type is an error: upgrade the SDK first.
- `helios.openapi()` returns the server's OpenAPI document, which the contract test compares with the SDK surface.

## Integration checklist: bella

Bella is account 1. Kodak keeps the raw store and CDN (`assets.lionize.ai`, `${stage}-kodak-media`). Helios reads Kodak source objects and never changes them.

1. Create the account with the Kodak source bucket allowlisted (`admin.accounts.create` with `sourceBuckets`). Grant `s3:GetObject` on that bucket to Helios's role. Store the returned `webhookSecret` in bella's secrets (`setup/configuration.js`).
2. Create the bella preset: `presets.clone("generic", "bella")`, then adjust profiles with `addProfile`, `updateProfile` and `expectedVersion`.
3. Create the account key with `keys.create` and store it in bella's secrets. Bella's `api/helios.ts` builds one `Helios` client from config, following the Kodak client pattern.
4. Set the account destination to bella's webhook (`accounts.create({ destination })`, or `account.setDestination`). Run `destinations.test` and check `httpStatus`.
5. Webhook endpoint (`webhook/helios.ts` in bella): mount `express.raw({ type: "application/json" })` on this route only. Verify the signature over `rawBody` with `helios.webhooks.verify` (timing-safe, 300 s tolerance). Dedupe on `event.id`. Respond 2xx fast, then do the work.
6. Persist the Helios request id and the asset id on the bella video record when you create the encode. Map `request.completed` to that record by `data.asset.id`.
7. Map results into bella models when `request.completed` arrives: transcripts from `assets.transcripts(assetId)` (srt, vtt, txt urls, language, isTranslation), scenes from `assets.scenes(assetId)` (scene times, descriptions, people, products, representative still index), and outputs from `asset.outputs` (their `url` fields are CDN urls).
8. Use `item.completed` only for progress UI. Terminal state comes from `request.*`.
9. Deletion: when bella deletes a video, call `assets.delete(assetId)` and wait for `asset.deleted`. Kodak-owned source objects remain bella's to delete.
10. Errors in bella: map `ConflictError` on re-encode to "already processing", `UploadEncodeError` to "stored, encode again", and `RateLimitError` to a queued retry after `retryAfterMs`.
11. Browser uploads from bella-frontend: the backend starts the upload with `uploads.createMultipart` and passes `upload` to the page. Add the origin of each bella-frontend stage (for example `http://localhost:5173` in dev, the production host in prod) to that stage's `UPLOAD_ALLOWED_ORIGINS`. Keep three routes in bella's backend: start, renew (`signParts`, called on 403) and stored parts (`listParts`, for resume after a reload). Finish with `completeMultipart`. Never send the key to the page.

## Integration checklist: novel

Novel is account 2. Novel's Cloudinary transforms move to `images.url`.

1. Server-side only. The browser never holds a Helios key. Uploads go through novel's backend: `uploads.uploadAndEncode` for a file the backend already has, or `uploads.createMultipart` with `completeMultipart` for large files the backend streams from its own storage. Large browser uploads use `@partnrup/helios-sdk/browser` (see "Browser uploader"), with novel's backend creating, re-signing and completing the upload.
2. Preset: use `generic` until the `novel_video` preset ships in phase 1b. Then clone it into a tenant preset and version it with `expectedVersion`.
3. Images: replace Cloudinary URLs with `images.url(key, { w, h, c, g, b, q, f }, version)`. Use `asset.outputs[profile].key` for image outputs and `asset.outputs[profile].items[i].key` for stills.
4. Webhooks: same as bella, with novel's own secret and endpoint. Dedupe and sequence rules are identical.
5. EventBridge: if novel's infrastructure consumes events from a bus it owns, follow `guides/eventbridge.md` and use `webhooks.eventBridgeDetail` in the Lambda consumer.
6. Post-processing later: `assets.postProcess` for translations, transcripts and scenes on assets that were encoded without them.
7. Account features: `peopleAttributes` is off by default. Enable it with `admin.accounts.update` only where scene people are needed.
8. Browser uploads from novel: list each novel web origin per stage in `UPLOAD_ALLOWED_ORIGINS` (the dev origin locally, the production origin in prod), since bucket CORS is bucket-wide. Re-sign expired parts through novel's backend (`uploads.signParts`) and resume from `uploads.listParts` after a reload, so an interrupted upload does not restart.
